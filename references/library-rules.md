# 库公共规则（演出库 / 画风库共用）

两个库——`staging/` 演出库、`styles/` 画风库——都是**受控集合**，共用下面这套规则。
各自的「装什么 / 命中判定 / 现状索引」见各自的库文件。

## 库只收用户教的

入库有且仅有两条路径：

1. 用户显式说"教你一个画风 / 一套演出" → 走入库流程。
2. 任务里现生成、效果得到用户确认 → **由用户点头后**入库。

**任务未命中库时，默认不入库。**

## 任务时的链路

```
查库
   ├─ 命中 → 直接套用该原子
   └─ 未命中 → 按该库的生成法现生成（默认不入库；效果好、用户点头才入库）
```

两个库的差异只在"谁来定"：

- **演出库**：按「角色能力类型 + 所选海报风格」推荐 2–3 档，**每档给一句理由，并说明与所选海报风格的适配 / 冲突**，用户定档。
- **画风库**：用户指定或暗示；**用户没指定 → 从库里给 2–3 个候选并说明各自调性**，让用户选。

## 入库流程

1. 生成原子文件——演出 = `STAGE.md` + `META.md`；海报风格 = `STYLE.md` + `META.md`。格式见各自的生成法。
2. `id` 用小写 kebab-case，全库唯一。
3. 写入 `staging/{id}/` 或 `styles/{id}/`。
4. 不覆盖同名；重名先向用户确认。

## 唯一来源提醒

**库里的原子是权威。** 库文件与 `SKILL.md` 里的任何"现状清单"都只是**索引**，与原子冲突时以原子为准。
